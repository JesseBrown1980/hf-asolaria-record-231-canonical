**Note — an elevated reading, why it was wrong, and what it was.**

**The first pass over item 3 did not produce `+13.1`. It produced `+40.3`**, more
than twice its seven immediate neighbours, using the same 44 × 26 box-sweep that
sections 121 and 124 used. **That number is left standing here rather than
deleted**, because a record that quietly repairs itself is not a record.

It is wrong, and the cause is now identified exactly. The sweep was re-run with
the horizontal range extended to `x ∈ [940, 1060]` and it reproduces an elevated
value — **`+47.5`, at window origin `(940, 1230)`, reading `68.0 / 106.1 /
115.5`.** A vertical pixel probe down `x = 940` shows why:

```

(940, 1247) = (65, 103, 106)   bubble edge
(940, 1250) = (69, 108, 123)   WALLPAPER, in the gap between two bubbles
(940, 1253) = (51, 91, 90)     next bubble edge
(940, 1256) = (38, 75, 57)     bubble green
```

**The window straddled the six-pixel gap between two bubbles and caught the
wallpaper showing through it.** Of the 1,144 pixels in that window, **202 —
17.7 % — carry the wallpaper's signature `B ≥ R + 40`**, and a
brightest-twenty-per-cent selection is made almost entirely out of them.

**The wallpaper is blue-over-red by `+71.3`. The maximiser was told to find
blue, and it found the only blue in the neighbourhood, which was not a tick.**

**Walking the window across `x` shows the same thing from the other side:**

```

```

The value climbs as the window slides off the timestamp text and onto the ticks,
**plateaus between `x = 994` and `x = 1018`, and falls again as the window runs
off the bubble's right edge into the wallpaper.** A pixel probe across that row
puts the bubble green out to `x = 1020` and the wallpaper from `x = 1030`.

**Three independent procedures now agree that item 3 is grey**: the row-run
measurement `+13.1`, the plateau of the window walk `+18.5` to `+18.8`, and the
seven neighbours it sits between. **The two procedures disagree about the number
by five levels and neither was adjusted to match the other** — the row-run box is
tighter and includes more dark background, which pulls the ratio down. **What
neither of them is, is eighty.**

**The general lesson is written down because this record will use the same tool
again:** a maximiser is not a measurement. It returns the most extreme window in
a range, and if the range contains something more extreme than the thing being
measured, that is what comes back. **Every sweep in this record is now suspect
in exactly one way — whether its search range was clean — and that is a
checkable question rather than a matter of trust.**
